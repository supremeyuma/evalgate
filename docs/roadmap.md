## E2 — Providers, metrics, runner, CLI (M1)

- [x] OpenAI-compatible + Anthropic adapters with retry/timeout
- [x] Mock/replay providers; deterministic metrics
- [x] Bounded-concurrency runner, rich table, exit codes 0/1/2/3

**Gate evidence:** `uv run evalgate run examples/support/suite.yaml --mock` → 40/40 pass,
exit 0, JSON + HTML artifacts written. Classification suite → 30/30. Adapters are covered

small-sample cases. 173 tests, 94% coverage, mypy strict clean, zero live calls.

## E3 — LLM judges, caching, calibration (M2)

- [x] Anchored rubric prompt + strict JSON contract + repair attempt
- [x] Content-addressed judge cache (Postgres + local)
- [x] Two-judge calibration with agreement/kappa
- [x] Failure-path tests

**Gate evidence:** judge output is parsed strictly (fenced JSON, prose, out-of-range,
missing fields) with one repair attempt; refusals score 1 with a documented flag; provider
failure records `judge_error` without crashing the run. Cache: cold support run → 40 judge
calls, 0 hits; warm run → 0 calls, 40 hits. Rubric edits invalidate. Local SQLite backend
plus Postgres backend (integration test runs under Docker; `judge_cache` upsert is
idempotent). Calibration: `evalgate calibrate --suite examples/support/suite.yaml --mock
--cases 30` → exact 100%, within-1 100%, kappa 1.000, labelled mock in
[`calibration.md`](calibration.md). 198 tests, 93% coverage, mypy strict clean. ADR-004
records the cache key.

## E4 — Persistence, concurrency, baselines (M3)

- [x] SQLAlchemy + Alembic schema, ARQ worker
- [x] Wilson interval, p95, cost aggregation
- [x] Regression rule with interval overlap + truth-table tests
- [x] Thin API with API-key auth

**Gate evidence:** Alembic `0001` upgrades and downgrades cleanly against Postgres 16
(`tests/integration/test_migrations.py`). Repository covers create/record/finalize, baseline
by `git_ref` or explicit id, list runs, and idempotent result upserts (a repeated
`record_results` leaves the row count unchanged). API: `X-API-Key` auth (401 without),
`POST /v1/runs` from a suite path or inline YAML, `GET /v1/runs/{id}`,
`report.{json,html}`, `/healthz`, `/readyz`, structured request logs with `X-Request-ID`,
OpenAPI at `/openapi.json`. ARQ worker executes the same service and publishes progress to
Redis (`evalgate:progress:<id>` = 100). 215 tests (16 integration against real Postgres and
Redis containers), 92% coverage, mypy strict clean.

## E5 — GitHub Action and PR reporting (M4)

- [x] Composite action, artifacts, idempotent PR comment
- [x] Example consumer workflow
- [x] Flaky-run policy documented

**Gate evidence:** `actionlint` (rhysd/actionlint container) exits 0 over the action, CI, and
consumer workflows. The comment is ASCII-safe, carries exactly one
`<!-- evalgate:report -->` marker, renders baseline/current/delta/verdict, hard-limit
banners, judge cache stats, and up to ten regressed cases with per-metric detail (15 tests,
including gh create/update/read-only paths). The consumer example ships a committed baseline
and runs offline: `scripts/demo_ci.ps1` → `DRY RUN COMPLETE (exit 0)`. Provider/judge
retries and the stricter "errors exit 3" flaky policy are documented in
[`failure-modes.md`](failure-modes.md), with a deviation note from the plan's
"mark flaky and pass" default.
