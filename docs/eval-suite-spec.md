# Eval suite specification

An eval suite is one YAML file. It names a model, a prompt template, a JSONL dataset, and
the metrics that decide whether a response passes. The YAML contract is validated strictly:
unknown keys are rejected, so a typo cannot silently disable a metric.

- Canonical JSON Schema: [`docs/schema.json`](schema.json), generated by
  `evalgate schema -o docs/schema.json`. A test fails if this file drifts from the models.
- Example suites: [`examples/support/suite.yaml`](../examples/support/suite.yaml) and
  [`examples/classification/suite.yaml`](../examples/classification/suite.yaml).

## Annotated example

```yaml
name: support-reply-quality          # required, non-empty
model:
  provider: mock                     # openai-compatible | anthropic | mock
  name: gpt-4.1-mini                 # required
  temperature: 0                     # 0..2, default 0
  max_tokens: 512                    # > 0, default 1024
  base_url: https://api.openai.com/v1  # optional; http(s) only

prompt: prompts/support.md           # Jinja2 template, relative to this suite file
cases_file: datasets/support.jsonl   # JSONL, relative to this suite file

metrics:                             # at least one
  - type: json_schema_valid
    schema: schemas/reply.json       # JSON Schema file, validated at load time
  - type: contains
    value: ["answer", "citations"]   # string or list of strings
    mode: all                        # any (default) | all; case-insensitive
  - type: llm_judge
    rubric: rubrics/helpfulness.md   # optional if suite.judge.rubric is set
    threshold: 4.0                   # required, 1..5 raw rubric score
  - type: latency_ms
    max: 4000                        # optional; falls back to limits.max_p95_latency_ms
  - type: cost_usd
    max: 0.01                        # optional; falls back to limits.max_cost_usd

limits:                              # hard limits fail the run regardless of pass rate
  max_cost_usd: 0.50
  max_p95_latency_ms: 4000

regression:
  max_pass_rate_drop: 0.03           # 0..1, default 0.03 (3 points)
  min_cases: 10                      # below this, a drop is never a regression

judge:                               # defaults for llm_judge metrics
  model: gpt-4.1-mini
  rubric: rubrics/helpfulness.md
```

## Dataset format

One JSON object per line. Blank lines are ignored. Ids must be unique and contain no
whitespace; they are the join key for baseline diffs and judge caching.

```json
{"id":"sup-001","input":"...","context":"...","expected":"...","tags":["billing"]}
```

| Field | Required | Meaning |
|---|---|---|
| `id` | yes | Stable, unique case id. |
| `input` | yes | Rendered into the prompt as `{{ input }}`. |
| `context` | no | Rendered as `{{ context }}`; policy snippets or retrieved text. |
| `expected` | no | Reference answer or required facts. `exact_match` compares against it; judges receive it. |
| `tags` | no | Free-form labels; duplicates are collapsed. |

## Metric semantics

Every metric returns a score in `[0, 1]`, a pass/fail flag, and a detail string. **A case
passes only when every metric passes**; the run pass rate is the fraction of passing cases.
See [`adr/001-per-case-semantics.md`](adr/001-per-case-semantics.md).

| Type | Pass condition | Notes |
|---|---|---|
| `exact_match` | Response equals `case.expected` | `normalize: true` strips, lowercases, and collapses whitespace. A case without `expected` fails. |
| `contains` | `any`/`all` of the configured substrings appear | Case-insensitive. |
| `json_schema_valid` | Response parses as JSON and validates against the schema | Surrounding prose and ``` fences are tolerated when extracting JSON. |
| `regex` | `re.search(pattern, response)` matches | Patterns are compiled at load time; invalid patterns are rejected. |
| `llm_judge` | Judge score ≥ `threshold` (1–5) | Raw score and rationale are stored; normalized to `(score-1)/4`. |
| `latency_ms` | Latency ≤ `max`, or p95 limit when omitted | Provider-reported or measured wall clock. |
| `cost_usd` | Cost ≤ `max`, or the suite cost limit when omitted | Computed from the pricing table; unknown model costs 0 with a warning. |

## Path safety

- Every file reference resolves relative to the directory containing the suite file.
- Absolute paths are rejected.
- A resolved path must remain inside the project root: the nearest ancestor containing
  `.git`, or the suite's own directory when there is no repository. `..` escapes are
  rejected, as are symlinks that resolve outside the root.
- Referenced prompts, datasets, schemas, and rubrics must exist at validation time;
  JSON Schemas are also checked for structural validity.

## Exit codes

| Code | Meaning |
|---|---|
| `0` | Valid suite / passing run |
| `1` | Quality gate failed (regression or hard limit) |
| `2` | Invalid suite, configuration, or usage |
| `3` | Infrastructure error (provider unreachable after retries) |
